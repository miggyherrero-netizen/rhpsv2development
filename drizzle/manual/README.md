# Manual migrations (live database)

The Vercel deploy only runs `next build` — it does **not** change the database. Before using a deploy that needs a
new column, run the matching file here on the live database (psql, or the Neon / Supabase SQL console).

Run them **in order**. Each one is additive (`ADD COLUMN IF NOT EXISTS`, defaults, no deletes or rewrites) and safe to run twice.

| # | File | Needed by |
|---|------|-----------|
| all | `00_ALL_IN_ONE.sql` | The four files below combined — easiest: paste this one |
| 1 | `01_phase1_inline_lines.sql` | Inline quote/invoice lines: quick-add chips, packages, per-line cost |
| 2 | `02_phase3_expense_kind.sql` | Expense kind (job / stock / overhead), piano link, review screen, Finance split |
| 3 | `03_phase4_status_time.sql` | Status = time (status events derive travel / on-site entries) |
| 4 | `04_phase5_piano_sale.sql` | Piano sale jobs |

| 5 | `05_waitlist_schema.sql` | Waitlist by Area: geography tables, locations city, trips, waitlist, templates, routes |
| 6 | `06_ph_geo_seed.sql` | Waitlist: Mindanao regions, provinces, 455 cities/municipalities (with lat/lng), Davao City barangays (generated by `scripts/gen-ph-geo.mjs` + `scripts/gen-ph-geo-sql.mjs`) |
| waitlist | `00_WAITLIST_ALL_IN_ONE.sql` | Files 5 + 6 combined — paste this one (after `00_ALL_IN_ONE.sql`) |
| 8 | `08_line_details.sql` | Quote / invoice lines get an optional **Details** text (small print under the item name); packages become one price + an "includes" list |
| 9 | `09_finance_history.sql` | Finance history: `service_finance_history` table (what every money edit was before -> after). The app works without it, but nothing is recorded until it is run |
| 7 | `07_reminders.sql` | Client follow-up reminders: `service_reminders` table (+ status enum) |
| 10 | `10_recalc_job_parts_cost.sql` | Job cost rules: refreshes the derived `service_jobs.parts_cost_cents` (part lines with no cost now cost 0). Optional, no schema change; clears Finance health parts-drift warnings on old jobs |
| 11 | `11_invoice_kind.sql` | Invoice type: `service_invoices.kind` ('service' default, or 'sale' for a piano sale). Run it FIRST: until then invoice pages and the dashboard error because the column is missing. Existing invoices stay 'service' |
| 12 | `12_maintenance_notifications.sql` | Maintenance Phase 1: one new table, `service_notification_preferences` (consent per customer). Read by `/service/maintenance`; the page works without it and shows "No consent recorded". Nothing writes it yet. Idempotent |

Phase 2 (Today command center) needs no schema change.

Each file was checked against a copy of the previous schema, and the result was compared with what `drizzle-kit push`
produces from `src/db/schema.ts` — the tables, columns, types, defaults, indexes and constraints match.
